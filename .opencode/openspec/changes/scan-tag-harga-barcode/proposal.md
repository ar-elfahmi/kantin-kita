## Why

M1 SK1 shipped the ability to **generate** scannable price tag PDFs with Code128 barcodes encoding each menu's `id_barang`. The reciprocal scan flow was missing.

The existing sidebar Scan Barcode modal in `dashboard-vendor.blade.php` is **dedicated to order receipts** (the QR generated by M1 SK2 after a Midtrans settlement, format `KK-{pesanan_id}-{timestamp}`). Mixing tag-harga scanning into that modal would conflate two distinct workflows (verifying a customer's paid order vs. looking up a product by its label) and confuse the operator who triggered the scan.

This change keeps the order scanner exactly as it is and adds a **separate dedicated page** for scanning tag harga barcodes, reachable from the Tag Harga management page.

## What Changes

- New controller method `PriceTagController::scan()` returning a full vendor-dashboard page with its own scanner widget
- New auth-protected route `GET /dashboard/menu/scan` named `dashboard.menu.scan`
- New JSON endpoint `PriceTagController::lookupByIdBarang(string $idBarang)` returning vendor-scoped menu data
- New auth-protected route `GET /api/menu/by-id-barang/{idBarang}` named `api.menu.by-id-barang`
- New Blade view `resources/views/vendor/scan-tag-harga.blade.php` — two-column layout (scanner panel | result panel) reusing the existing dashboard sidebar partial; uses `html5-qrcode` CDN; falls back to a manual 8-char input
- New "📷 Scan Tag Harga" CTA on `vendor/manage-menu.blade.php` panel header (next to the menu count) navigating to the new page
- Sidebar "Tag Harga" active state updated from `routeIs('dashboard.menu')` to `routeIs('dashboard.menu*')` so the nav-item stays highlighted on both the list page and the scan page (3 files: shared `_sidebar` partial + 2 inline dashboards)

## Capabilities

### New Capabilities
- `tag-harga-scan`: Vendor can scan a printed tag harga barcode from a dedicated scanner page and view full menu details

### Modified Capabilities
- (none — the existing `vendor-scan-barcode` capability for order receipts is untouched)

## Impact

- Two new PHP controller methods on `PriceTagController` (~50 LOC total)
- Two new routes inside the existing `auth` group
- One new full-page Blade view (~340 LOC) using the shared sidebar partial
- Two existing files modified for nav-item active-state pattern matching + CTA placement
- Zero changes to the existing order-scanner modal or its JS
- Zero new Composer dependencies
- Zero DB / migration changes

## Design pivot from initial approach

This change originally proposed extending the sidebar order scanner with a format-dispatcher (`KK-*` → order, `[A-Z0-9]{8}` → menu). User feedback noted that the order scanner is purpose-built for post-payment verification and a separate page is the cleaner UX. The initial implementation was reverted; the order scanner is back to its original state, and the menu-scan flow is now a standalone page reachable from `/dashboard/menu`.
